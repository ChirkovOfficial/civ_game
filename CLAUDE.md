# CLAUDE.md — правила работы над проектом

Пошаговая 4X-стратегия по мотивам Civilization VI на **Godot 4.7 (GDScript)**.
Команда — двое: владелец проекта (художник; 2D, арты, заставки; в коде разбирается мало)
и Claude (весь код, 3D-сборка, техническая часть).

**Общение и комментарии — на русском.** Идентификаторы в коде и данных — латиницей.

## С чего начинать каждую сессию

1. Прочитать `docs/STATUS.md` — где остановились и что дальше.
2. Сверяться с `docs/GDD.md` (дизайн-документ, источник правил и чисел) и `docs/ARCHITECTURE.md`.
3. В конце сессии обновить `docs/STATUS.md` и закоммитить.

## Как запускать (в рабочей среде Claude)

Godot в контейнер не установлен — скачать официальную сборку:
```bash
mkdir -p ~/tools && cd ~/tools
curl -sSL -o godot.zip https://github.com/godotengine/godot/releases/download/4.7.2-stable/Godot_v4.7.2-stable_linux.x86_64.zip
unzip -o -q godot.zip && chmod +x Godot_v4.7.2-stable_linux.x86_64
ln -sf ~/tools/Godot_v4.7.2-stable_linux.x86_64 ~/.local/bin/godot
```
Затем из корня репозитория:
```bash
godot --headless --path . --import                      # один раз: кэш классов
godot --headless --path . -s tools/check_scripts.gd     # компиляция всех скриптов
godot --headless --path . -s tests/run_tests.gd         # все тесты, код 0 = ок
TEST_FILTER=test_movement godot --headless --path . -s tests/run_tests.gd
xvfb-run -a -s "-screen 0 1600x900x24" godot --path . -s tools/screenshot.gd -- out.png <зерно> [reveal|fog] [дистанция] [path|-] [ходов автоигры]
xvfb-run -a -s "-screen 0 1600x900x24" godot --path . -s tools/smoke_view.gd   # дымовой тест интерфейса
godot --headless --path . -s tools/autoplay.gd -- 120 SMALL 3                    # автоигра ИИ, статистика
```
Рендерер проекта — **Compatibility (OpenGL)**: так скриншоты в контейнере (Mesa llvmpipe)
совпадают с тем, что видит игрок. Свет в этом рендерере считается в sRGB.

## Архитектура — обязательные правила (ГДД 25.1)

- `core/` — чистая симуляция: никакого рендеринга, ввода и узлов сцены. Классы `RefCounted`.
- Мир меняется **только** через `Game.apply_action(dict)` → список событий. ИИ и интерфейс
  используют один и тот же API.
- **Весь контент и баланс — в `data/*.json`.** В коде нет id конкретного контента, кроме
  ссылок через `constants.json`. Новое правило с числами → число в данные.
- **Детерминизм:** единственный ГПСЧ — `state.rng` (`GameRng`). Системный `randf()/randi()`
  в `core/` запрещён. Перебор словарей — в отсортированном порядке, если влияет на результат.
- Состояние полностью сериализуемо (`GameState.to_dict/from_dict`); новое поле состояния →
  добавить в сериализацию и в тест `test_save_load_roundtrip`.
- `view/` — отображение и ввод; читает состояние, но не меняет его напрямую.
- Каждая механика — с тестами в `tests/test_*.gd` (наследники `TestCase`, методы `test_*`).

## Подводные камни GDScript (Godot 4.7)

- Вывод типа из Variant (`var x := dict.get(...)`, `var x := arr[i]` из нетипизированного
  массива) — **ошибка компиляции** в этом проекте. Писать явный тип: `var x: int = ...`.
- `Array[int] + Array[int]` даёт нетипизированный `Array` — собирать через `append_array`.
- JSON возвращает числа как `float`: при загрузке приводить к `int` (`Unit._ints_in_dict`).
- После добавления нового `class_name` перезапустить `--import`, иначе класс не найдётся.
- Интерфейс: панели с якорями добавлять в дерево **после** установки якорей и `position`
  (см. `Hud._attach`), иначе позиция считается от левого верхнего угла родителя.
- Лямбды захватывают переменные цикла по значению — так и задумано в кнопках HUD.
- Варвары — отдельный `Player` с `is_barbarian = true` в конце `state.players`; циклы по
  державам должны его пропускать. Ходят раз в круг (`Game._barbarian_phase`).
- `Unit.tile` менять можно напрямую: сеттер сбрасывает индекс `GameState.units_at`.

## Работа с владельцем проекта

- Объяснять просто, без жаргона; показывать результат скриншотами (`tools/screenshot.gd`).
- Арты владелец кладёт в `art/` (см. `art/README.md`); код к ним подключает Claude.
- Если в ГДД неясность или решение влияет на геймплей — спросить, а не угадывать.
- Коммиты — в ветку `dev`; в `main` — по договорённости с владельцем.
